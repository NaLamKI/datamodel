AgriFoodData API

OpenAPI 3.1 · 1.0.0-draft.3 · openapi.yaml · openapi.json

Reference REST binding of the AgriFoodData model — the data model of the Recommendation Data model for digital agriculture and farm management systems (draft, revision 3, proposed to ITU-T Study Group 20, 2026-07-29).

The resources and their attributes are the entities of the model; each attribute maps onto a property of the agrifooddata ontology. The paths, headers and status codes are the binding of this repository — the Recommendation specifies the data and the requirements of its clauses 9 and 10, not a REST interface.

Representations. JSON as specified in clause 9: camelCase, UTC timestamps, GeoJSON geometries, enumerations in upper case, identifiers as strings. Optional attributes that are not set are omitted, never null. Asked for application/ld+json, the server adds three JSON-LD keywords in front — @context (https://datamodel.agrifooddata.org/v1/context.jsonld), @id (urn:uuid: and the id) and @type (the entity) — and leaves the attributes as they are.

Identifiers are UUIDs in lower case, generated by the client that creates a record, so that records created while offline do not collide.

Synchronization. Every collection lists in the order of updatedAt, then id; a client polls each collection with the cursor of its last page. Withdrawals arrive as status changes, deletions as DELETE entries of /audit-logs. Writes conflict per attribute, and the later write wins (clause 5.1 b)); documentation already reported is corrected only with a Change-Reason (correction path).

Provenance (clause 5.1 l)). The server sets createdAt, updatedAt, createdByUserId, createdByJobId and clientId from the authenticated caller. A processing run that writes names its ProcessingJob in the Processing-Job-Id header; every automatic creation of data is such a run.

Security (clause 10). Every request is authenticated through the external identity and access management system (OpenID Connect) and authorized against its policies; the roles and access assignments of the model are evaluated in addition, never instead. x-agfoda-permission names the permission, in the entity:action pattern of Role.permissions, that an operation requires on the farm concerned.

Problems are reported as RFC 9457 problem details; their type is https://datamodel.agrifooddata.org/v1/problems/:

Type Status Meaning
invalid-record 422 The record does not conform to its schema
rule-violation 422 An integrity rule is violated
invalid-transition 409 The status change is not permitted
immutable-record 409 The record can no longer be changed
duplicate-key 409 A business key is already taken
reason-required 422 A correction needs a reason
dependent-records 409 Other records depend on this one

The geospatial entities Field, Region and Site are also served as feature collections conforming to OGC API - Features (/features).
